    14. FollowTarget и FleeTarget во времени: выборка, кеш команды, гистерезис¶

    Коротко

    FollowTarget и FleeTarget — runtimes, которые поддерживают отношение к живой цели: держаться рядом или убегать. Они читают текущие transforms агента и цели, пересчитывают steering с интервалом (по умолчанию 0.05 с), но применяют сохранённое намерение на каждом tick, потому что команда персонажа живёт один кадр. Flee использует два порога расстояния и память состояния — гистерезис, исключающий дребезг на границе. Оба runtimes не завершаются успехом сами: они работают, пока их не отменят или цель не исчезнет. Статус: SOURCE_VERIFIED.

    1. Задача и интуиция¶

    move_to из ассетов ведёт к снимку позиции роли (глава 06) и завершается. Для подвижной цели нужно другое: каждую долю секунды заново смотреть, где цель, и корректировать движение. Два практических вопроса: как часто пересчитывать (стоимость probes avoidance против отзывчивости) и как не «дрожать», когда расстояние до угрозы колеблется около порога.

    2. Теоретическая выкладка¶

    2.1. Выборка и удержание (sample-and-hold)¶

    Пусть интервал выборки TTT, кадровый шаг Δtk\Delta t_kΔtk​. Накопитель eke_kek​:

    ek=ek−1+Δtk,если ek≥T:  пересчёт,  ek←ek mod T. e_{k} = e_{k-1} + \Delta t_k,\qquad \text{если } e_k \ge T:\; \text{пересчёт},\; e_k \leftarrow e_k \bmod T . ek​=ek−1​+Δtk​,если ek​≥T:пересчёт,ek​←ek​modT.

    Между пересчётами используется последнее намерение u∗u^\astu∗ (удержание нулевого порядка). Свойства:

    • средняя частота пересчётов ≈1/T\approx 1/T≈1/T без накопления дрейфа (остаток  mod T\bmod TmodT переносится);
    • нет догоняния: после длинного кадра (Δt≫T\Delta t \gg TΔt≫T) выполняется один пересчёт, а не ⌊Δt/T⌋\lfloor \Delta t / T \rfloor⌊Δt/T⌋ — это не симуляция пропущенных подшагов;
    • задержка реакции на движение цели — до TTT плюс кадр; при T=0.05T = 0.05T=0.05 и 60 Гц пересчёт раз в 3 кадра;
    • T≤0T \le 0T≤0 означает пересчёт на каждом tick.

    Почему удержанное намерение надо переиздавать: GameplayCharacterCommandComponent очищается в BeginFrame (GR-RESET-FRAME). Если писать команду только в кадр пересчёта, в двух кадрах из трёх команда будет нулевой, и мотор будет разгоняться и тормозить — движение «рывками».

    2.2. Follow: поддержание, а не достижение¶

    Follow на каждом пересчёте вызывает Seek к текущей позиции цели с радиусом приёма rrr (по умолчанию 0.25). Внутри rrr Seek даёт нулевую команду, но runtime остаётся Running: смысл действия — «держаться рядом»; если цель отойдёт, следующий пересчёт снова даст движение. Замедления у цели нет (Seek, не Arrival): агент подходит с полной интенсивностью и тормозит мотором (NA-FOLLOW-TICK).

    2.3. Flee и гистерезис¶

    Пусть ddd — горизонтальная дистанция до угрозы, s∈{0,1}s \in \{0, 1\}s∈{0,1} — «бежит». С одним порогом θ\thetaθ правило s=[d≤θ]s = [d \le \theta]s=[d≤θ] переключает состояние при каждом пересечении θ\thetaθ; шум расстояния амплитуды ε\varepsilonε даёт дребезг, как только ∣d−θ∣<ε|d - \theta| < \varepsilon∣d−θ∣<ε. Гистерезис вводит два порога θt≤θs\theta_t \le \theta_sθt​≤θs​ (trigger и safe) и память:

    sk={[ dk<θs ],sk−1=1,[ dk≤θt ],sk−1=0. s_{k} = \begin{cases} [\, d_k < \theta_s \,], & s_{k-1} = 1,\\ [\, d_k \le \theta_t \,], & s_{k-1} = 0 . \end{cases} sk​={[dk​<θs​],[dk​≤θt​],​sk−1​=1,sk−1​=0.​

    В «зоне памяти» (θt,θs)(\theta_t, \theta_s)(θt​,θs​) результат определяется прошлым состоянием. Чтобы шум не переключал состояние, достаточно, чтобы его размах был меньше ширины зоны: 2ε<θs−θt2\varepsilon < \theta_s - \theta_t2ε<θs​−θt​. Конструктор приводит параметры к θt≥0\theta_t \ge 0θt​≥0 и θs≥θt\theta_s \ge \theta_tθs​≥θt​ (NA-FLEE-CTOR); при θs=θt\theta_s = \theta_tθs​=θt​ гистерезис вырождается в один порог (с несимметричными ≤\le≤/<<<). Значения по умолчанию — 2 и 3 м, интервал 0.05 с (NA-FLEE-SETTINGS). Направление бегства — Flee steering (от угрозы, magnitude 1, глава 13); при совпадении позиций — ноль.

    Состояние sss обновляется только при пересчёте: между пересчётами переиздаётся последнее решение.

    2.4. Время жизни цели и ориентация¶

    На каждом tick runtime проверяет, что агент и цель — валидные сущности с нужными компонентами; иначе команда обнуляется и результат Failed. Цель — живая сущность (handle), а не снимок позиции; но и здесь пересоздание сущности с новым handle не отслеживается. При ненулевой команде desiredFacingYawDegrees берётся из итогового направления команды (после avoidance), в том числе в тиках без пересчёта (NA-FOLLOW-RT).

            [[nodiscard]] AIActionRuntimeResult Tick(
            const AIActionRuntimeContext& context,
            const float deltaSeconds) override
        {
            if (!Validate_(context))
            {
                ClearMovementIfAccessible_(context.agentEntity);
                return AIActionRuntimeResult::Failed;
            }

            if (std::isfinite(deltaSeconds) && deltaSeconds > 0.0f)
            {
                elapsedSinceSteeringUpdate_ += deltaSeconds;
            }

            if (settings_.steeringUpdateIntervalSeconds <= 0.0f ||
                elapsedSinceSteeringUpdate_ >= settings_.steeringUpdateIntervalSeconds)
            {
                RefreshSteering_(context.agentEntity);
                elapsedSinceSteeringUpdate_ =
                    settings_.steeringUpdateIntervalSeconds > 0.0f
                    ? std::fmod(
                        elapsedSinceSteeringUpdate_,
                        settings_.steeringUpdateIntervalSeconds)
                    : 0.0f;
            }
            // GameplayCharacterCommandComponent is frame-local and is cleared
            // by GameplayRuntime::BeginFrame(). Steering is intentionally
            // sampled at a lower cadence, so re-issue the last sampled intent
            // every AI tick without re-running steering or obstacle probes.
            ApplyCurrentMovement_(context.agentEntity);
            return AIActionRuntimeResult::Running;
        }

            void RefreshSteering_(const EntityHandle agentEntity) noexcept
        {
            const mathUtils::Vec3 agentPosition = world_.TryGetTransform(agentEntity)->position;
            const mathUtils::Vec3 targetPosition = world_.TryGetTransform(targetEntity_)->position;
            mathUtils::Vec3 planarDelta = targetPosition - agentPosition;
            planarDelta.y = 0.0f;
            const float distance = mathUtils::Length(planarDelta);

            if (isFleeing_)
            {
                isFleeing_ = distance < settings_.safeRadius;
            }
            else
            {
                isFleeing_ = distance <= settings_.triggerRadius;
            }

            GameplayMovementIntent movement = isFleeing_
                ? BuildGameplayFleeSteering(agentPosition, targetPosition, settings_.steering)
                : GameplayMovementIntent{};
            GameplayObstacleAvoidanceDebugSnapshot debug{};
            const bool debugEnabled = debugRegistry_ != nullptr && debugRegistry_->IsEnabled();
            if (debugEnabled)
            {
                debug.baseMovement = movement;
                debug.finalMovement = movement;
            }
            if (obstacleQuery_ != nullptr)
            {
                movement = ApplyGameplayAgentObstacleAvoidance(
                    world_, agentEntity, movement, *obstacleQuery_, obstacleSettings_,
                    obstacleAvoidanceState_, debugEnabled ? &debug : nullptr);
            }
            if (debugEnabled)
            {
                debugRegistry_->Publish(agentEntity, GameplaySteeringDebugMode::Flee, debug);
            }

            currentMovement_ = movement;
        }

    4.3. Как запускаются¶

    Только прямыми вызовами GameplayRuntime::StartAIFollowTarget / StartAIFleeTarget (GR-START-FOLLOW, GR-START-FLEE): им передаются obstacle query и steering debug (navigation debug не нужен — маршрута нет). В ассетной GOAP-композиции зарегистрированных capability для Follow/Flee нет (встроены только move_to и purchase) — использовать их как шаг плана можно только программно, с собственным binding и осмысленным terminal-контрактом SOURCE_VERIFIED.

    5. Разобранный пример: Steering Playground¶

    Сценарий (AS-SC-PLAYGROUND) и уровень: Steering_Flee_Agent (0, 0, 0), Steering_Flee_Threat (3, 0, 0), trigger 5, safe 7, ходьба; Steering_Follow_Agent (−8, 0, −6) → Steering_Follow_Target (8, 0, −6), acceptance 0.8, ходьба.

    Flee. Старт: d=3≤5d = 3 \le 5d=3≤5 → бежит; направление (0−3,0−0)/3=(−1,0)(0 - 3, 0 - 0)/3 = (-1, 0)(0−3,0−0)/3=(−1,0) — к −X-X−X. Позади агента стоит Steering_Flee_Obstacle (−2, 0.9, 0) — avoidance скорректирует направление (глава 15). Агент удаляется со скоростью до 2 м/с; когда ddd достигнет 7 (примерно через 2 с без учёта обхода), состояние перейдёт в «спокоен» и команда станет нулевой. Если затем угрозу придвинуть на 6 м, агент останется стоять (6 > 5); если бы он ещё бежал, продолжил бы (6 < 7).

    Follow. d=16d = 16d=16, Seek → (1,0,0)(1, 0, 0)(1,0,0), magnitude 1, 2 м/с; посередине — Steering_Follow_Obstacle (0, 0.9, −6). Когда агент войдёт в 0.8+0.0010.8 + 0.0010.8+0.001 от цели, команда станет нулевой, но runtime останется Running.

    Выборка при 60 Гц (Δt≈0.0167\Delta t \approx 0.0167Δt≈0.0167): пересчёты на 3-м (или 4-м — из-за округления float) тике, команда — в каждом кадре.

    6. Типичные ошибки, границы и проверка¶

    • Ждать успеха Follow. Runtime не завершается сам — нужен внешний CancelAIAction или своя логика.
    • Писать команду только при пересчёте. Рывки; runtimes CoreEngine переиздают намерение.
    • Один порог Flee. Дребезг; используйте ширину зоны больше шума.
    • Длинный кадр. Один пересчёт, без догоняния.
    • Высота. Дистанции горизонтальные: угроза этажом выше «рядом».
    • Пересоздание цели. Новый handle не отслеживается; runtime упадёт в Failed.
