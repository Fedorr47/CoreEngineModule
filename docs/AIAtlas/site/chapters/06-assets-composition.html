    06. Ассеты и композиция: catalog, behavior, bindings, template и instance¶

    Коротко

    Поведение собирается из нескольких файлов с разной ответственностью и зарегистрированных компонентов. Сборка идёт в две стадии: при регистрации каталога всё, что не зависит от уровня и агента, разбирается, компилируется и проверяется в неизменяемый GameplayGOAPDecisionTemplate; при старте решения template связывается с уровнем (роли — снимок позиций и сущностей) и порождает instance со своими фактами, наблюдениями, провайдерами и bindings. Регистрация каталога транзакционна. Статус: SOURCE_VERIFIED.

    1. Задача и интуиция¶

    Если бы каждое поведение было классом C++, новое поведение требовало бы программиста и пересборки, а сценарная специфика проникала бы в общий runtime. CoreEngine разделяет: что знает агент и что он умеет (GOAP-определение), как факты вычисляются и как шаги исполняются (компоненты), где это происходит на уровне (bindings ролей). Новый вариант поведения часто сводится к новому набору JSON; новый тип наблюдения или исполнителя — к одному C++-компоненту с регистрацией, без правки общей композиции.

    2. Теоретическая выкладка¶

    2.1. Конвейер «разбор → компиляция → связывание»¶

    Сборка — это компилятор маленького языка поведения:

    1. Разбор (parse): JSON → типизированные структуры; ошибки формата (неизвестное поле, неверный тип, версия ≠ 1).
    2. Компиляция (compile): имена → идентификаторы, проверка символов, типов фактов, уникальности; результат не зависит от уровня.
    3. Связывание (link): имена ролей → узлы конкретного уровня и сущности; создание объектов, хранящих состояние.

    Принцип — проверять как можно раньше то, что можно проверить: всё, что зависит только от ассетов, проверяется при регистрации каталога (один раз на запуск), а зависимое от уровня — при создании instance. Ошибка второго рода не может быть обнаружена раньше: тот же behavior может быть корректен на одном уровне и некорректен на другом.

    2.2. Расширяемость через реестр (open/closed)¶

    Реестр компонентов хранит для каждого типа пару функций: parser (JSON → T) и compiler (T + контекст → объект). Поскольку типы параметров различны, контейнер хранит их как std::any, а компилятор извлекает ожидаемый тип Parameters<T> с проверкой. Это классический приём «открыт для расширения, закрыт для изменения»: добавление компонента не меняет общий код композиции и не требует закрытого std::variant со всеми встроенными типами. Цена — проверка типа в рантайме (ошибка «incorrect typed parameters», если parser и compiler несогласованы).

    std::any существует только на стадии авторинга. Рабочее состояние GOAP — по-прежнему фиксированный вектор bool/int (глава 03).

    2.3. Неизменяемый template и состояние на агента¶

    Template — неизменяемый снимок (shared_ptr<const ...>): все агенты одного решения разделяют разобранные ассеты и скомпилированное определение. Всё изменяемое — факты, память latch, позиция route follower, флаги реакций, буферы событий — создаётся заново для каждого instance. Это шаблон flyweight: разделяется тяжёлое и неизменное, дублируется лёгкое и изменяемое. Следствие: прогресс одного агента не может «протечь» в другого, а пересоздание каталога не затрагивает уже работающие instance (они держат свой shared_ptr).

    2.4. Транзакционная публикация¶

    Регистрация каталога работает по схеме copy → modify → swap: строится копия реестра фабрик, в неё добавляются все записи, и только после успеха всех записей копия заменяет оригинал. Свойство «всё или ничего»: ошибка в последнем behavior не оставляет половину каталога зарегистрированной. Формально, если RRR — реестр до вызова, а EiE_iEi​ — успех iii-й записи, то результат

    R′={R∪{f1,…,fn},⋀iEi,R  (и исключение),иначе. R' = \begin{cases} R \cup \{f_1, \dots, f_n\}, & \bigwedge_i E_i,\\ R \;(\text{и исключение}), & \text{иначе}. \end{cases} R′={R∪{f1​,…,fn​},R(и исключение),​⋀i​Ei​,иначе.​

    2.5. Раннее связывание ролей¶

    Роль связывается один раз при создании instance: позиция берётся из LevelAsset.nodes[i].transform.position, сущность — из единственной gameplay-сущности с NodeLink на этот узел. Это раннее связывание: дешёвое и детерминированное, но не отслеживающее движение. Если цель переедет, наблюдения и маршруты будут работать с исходной позицией; если сущность пересоздадут с новым handle, роль останется привязанной к старому. Для подвижных целей предназначены отдельные runtimes FollowTarget/FleeTarget (глава 14).

            [[nodiscard]] bool RegisterCapability(std::string_view type, AIActionId actionId,
            std::function<T(const GameplayAIComponentParseContext&)> parse,
            GameplayGOAPCapabilityCompiler compiler)
        {
            if (type.empty() || !actionId.IsValid() || !parse || !compiler || capabilities_.contains(type))
            {
                return false;
            }
            for (const auto& [name, entry] : capabilities_)
            {
                if (entry.actionId == actionId)
                {
                    return false;
                }
            }
            auto parsers = parsers_;
            if (!parsers.Register<T>(GameplayAIComponentKind::Capability, type, std::move(parse)))
            {
                return false;
            }
            capabilities_.emplace(std::string(type),
                GameplayGOAPCapabilityRegistration{actionId, std::move(compiler)});
            parsers_ = std::move(parsers);
            return true;
        }

        [[nodiscard]] const GameplayAIComponentParsers& AssetParsers() const noexcept { return parsers_; }

        class GameplayGOAPDecisionTemplate
    {
    public:
        GameplayGOAPDecisionTemplate(GameplayAIBehaviorAsset behavior, GameplayAILevelBindingsAsset bindings,
            const GameplayGOAPDefinitionAsset& definition, GameplayGOAPCompositionRegistry components,
            std::optional<GameplayAIRouteGraphAsset> graph = {})
            : behavior_(std::move(behavior)), bindings_(std::move(bindings)), graph_(std::move(graph)),
              components_(std::move(components)), definitionSource_(definition.source)
        {
            if (behavior_.model != "goap")
            {
                Fail_("unknown decision model '" + behavior_.model + "'");
            }
            if (!behavior_.routeGraph.empty() && !graph_)
            {
                Fail_("missing authored route graph input");
            }
            compiled_ = CompileGameplayGOAPDefinition(definition, components_.SemanticActions());
            for (const auto& observer : behavior_.observations)
            {
                if (components_.Observation(observer.type) == nullptr)
                {
                    Fail_("unknown observation type '" + observer.type + "'");
                }
            }
            for (const auto& reaction : behavior_.reactions)
            {
                if (components_.Reaction(reaction.type) == nullptr)
                {
                    Fail_("unknown reaction type '" + reaction.type + "'");
                }
            }
            std::set<std::string> boundContexts;
            std::map<std::string, std::vector<GameplayAICapabilityAsset>> groups;
            for (const auto& asset : behavior_.capabilities)
            {
                if (components_.Capability(asset.type) == nullptr)
                {
                    Fail_("unknown capability '" + asset.type + "'");
                }
                if (!boundContexts.insert(asset.context).second)
                {
                    Fail_("multiple capability bindings for '" + asset.context + "'");
                }
                const auto authored = std::ranges::find(definition.actions, asset.context,
                    &GameplayGOAPAuthoredAction::context);
                if (authored == definition.actions.end() || authored->action != asset.type)
                {
                    Fail_("capability does not match a definition action/context '" + asset.context + "'");
                }
                groups[asset.type].push_back(asset);
            }
            for (const auto& action : definition.actions)
            {
                if (!boundContexts.contains(action.context))
                {
                    Fail_("action context '" + action.context + "' has no capability binding");
                }
            }
            for (auto& [type, assets] : groups)
            {
                capabilities_.push_back({type, std::move(assets), *components_.Capability(type)});
            }
        }

        void RegisterGameplayAIDecisionAssets(GameplayAIDecisionFactoryRegistry& destination,
        const GameplayAIDecisionCatalogAsset& catalog, const GameplayGOAPCompositionRegistry& components)
    {
        std::set<std::string> ids;
        for (const auto& reference : catalog.decisions)
        {
            if (reference.id.empty() || destination.Contains(reference.id) || !ids.insert(reference.id).second)
            {
                goap_asset_composition_detail::Invalid(catalog.source, "empty or duplicate decision id '" + reference.id + "'");
            }
            if (reference.behavior.empty() || reference.bindings.empty())
            {
                goap_asset_composition_detail::Invalid(catalog.source, "empty asset reference for '" + reference.id + "'");
            }
        }
        auto pending = destination;
        for (const auto& reference : catalog.decisions)
        {
            const auto diagnosticPrefix = "Decision '" + reference.id + "' (behavior '"
                + reference.behavior + "', bindings '" + reference.bindings + "'): ";
            std::shared_ptr<const GameplayGOAPDecisionTemplate> prepared;
            try
            {
                auto behavior = LoadGameplayAIBehaviorAsset(reference.behavior, components.AssetParsers());
                auto bindings = LoadGameplayAILevelBindingsAsset(reference.bindings);
                const auto definition = LoadGameplayGOAPDefinitionAsset(behavior.definition);
                auto graph = behavior.routeGraph.empty() ? std::optional<GameplayAIRouteGraphAsset>{}
                    : std::optional{LoadGameplayAIRouteGraphAsset(behavior.routeGraph)};
                prepared = std::make_shared<const GameplayGOAPDecisionTemplate>(std::move(behavior),
                    std::move(bindings), definition, components, std::move(graph));
            }
            catch (const std::exception& error)
            {
                goap_asset_composition_detail::Invalid(catalog.source, diagnosticPrefix + error.what());
            }
            const bool registered = pending.Register(reference.id,
                [prepared = std::move(prepared), diagnosticPrefix](const GameplayAIDecisionCreationContext& context)
                    -> std::unique_ptr<GameplayAIDecisionInstance>
                {
                    try
                    {
                        return CreateGameplayGOAPDecisionFromTemplate(context, *prepared);
                    }
                    catch (const std::exception& error)
                    {
                        if (context.diagnostic != nullptr)
                        {
                            *context.diagnostic = diagnosticPrefix + error.what();
                        }
                        return nullptr;
                    }
                });
            if (!registered)
            {
                goap_asset_composition_detail::Invalid(catalog.source, "duplicate decision id '" + reference.id + "'");
            }
        }
        destination = std::move(pending);
    }

        std::vector<GameplayAIResolvedRole> ResolveRoles(const GameplayAILevelBindingsAsset& bindings,
        const GameplayAIDecisionCreationContext& context)
    {
        std::vector<GameplayAIResolvedRole> result;
        std::set<std::string> names;
        std::vector<EntityHandle> entities;
        context.world.CollectNodeLinkEntities(entities);
        for (const auto& binding : bindings.roles)
        {
            if (binding.role.empty() || !names.insert(binding.role).second)
            {
                Invalid(bindings.source, "empty or duplicate role '" + binding.role + "'");
            }
            int nodeIndex = -1;
            for (std::size_t index = 0; index < context.level.nodes.size(); ++index)
            {
                const auto& node = context.level.nodes[index];
                if (node.alive && node.name == binding.node)
                {
                    if (nodeIndex != -1)
                    {
                        Invalid(bindings.source, "ambiguous node '" + binding.node + "'");
                    }
                    nodeIndex = static_cast<int>(index);
                }
            }
            if (nodeIndex == -1)
            {
                Invalid(bindings.source, "role '" + binding.role + "': missing node '" + binding.node + "'");
            }
            const auto position = context.level.nodes[nodeIndex].transform.position;
            if (!std::isfinite(position.x) || !std::isfinite(position.y) || !std::isfinite(position.z))
            {
                Invalid(bindings.source, "node '" + binding.node + "': position must be finite");
            }
            EntityHandle resolved = kNullEntity;
            for (const auto entity : entities)
            {
                const auto* link = context.world.TryGetNodeLink(entity);
                if (link != nullptr && link->nodeIndex == nodeIndex)
                {
                    if (resolved != kNullEntity)
                    {
                        Invalid(bindings.source, "node '" + binding.node + "': multiple gameplay entities");
                    }
                    resolved = entity;
                }
            }
            result.push_back({binding.role, resolved, position});
        }
        return result;
    }

    5. Разобранный пример: сборка Access Key¶

    1. Каталог (AS-CATALOG) содержит 5 решений; access_key и access_key_reserved используют одни и те же bindings — разные поведения на одном уровне.
    2. Компиляция определения: 14 bool + 1 int факт; 1 цель reachDestination (score 1); 14 действий → контексты 0..13 в порядке файла (13 move_to и buy_key); семантические ID из реестра: move_to → 2, purchase → 3.
    3. Template: capability-группы move_to (13 ассетов) и purchase (1); каждый контекст покрыт ровно одной capability; граф маршрутов загружен (routeGraph).
    4. Создание instance на уровне ai_goap_access_key_development: роли start → GOAP_Start (0, 0.03, 0), coinA → GOAP_Coin_A (−6, 0.35, −3) и т.д. (позиции — снимок узлов уровня).
    5. Наблюдения в авторском порядке: resource_ledger (выходы: coins, coin*Collected, hasAccessKey), три pickup_available, nearest_location (шесть at*), within_distance (вход hasAccessKey, выход atDestination). Вход последнего производит ledger, который стоит раньше, — порядок сохраняется. Если бы автор поставил within_distance первым, упорядочивание переставило бы его после ledger.
    6. Capabilities: MoveToCapability компилирует граф маршрутов (роли → узлы), для каждого контекста считает кратчайший путь и, так как routeCost: true, возвращает 13 cost overrides (стоимости — в главе 05); PurchaseCapability проверяет модель покупки (глава 17).
    7. InstanceDefinition — копия определения, где у 13 действий move_to стоимость 1 заменена длинами путей.
    8. Instance: реакция hide_on_purchase, bindings двух семантических действий, inspectPath: true → доступен планируемый путь в отладке.

    6. Типичные ошибки, границы и проверка¶

    • Ожидать hot reload. Изменения ассетов требуют пересоздания реестра фабрик (в App — пересоздание GameplayRuntime); живые instance сохраняют старую конфигурацию.
    • Опечатки в .goap.json. Лишние поля здесь не запрещены (в отличие от behavior/bindings/routes) — опечатка в необязательном поле (continuationCondition вместо continuationConditions) будет тихо проигнорирована INFERRED.
    • Роль как трекер. Роль — снимок; перемещение или пересоздание цели не отслеживается.
    • Неоднозначные узлы. Два живых узла с одним именем — ошибка создания, а не «первый найденный».
    • Пустой каталог. GameplayRuntime() без фабрик ничего не знает о каталоге (GR-CTOR).

    Проверки: TestGameplayAIAssetComposition.cpp (14), TestGameplayGOAPDecisionTemplate.cpp (4), TestGameplayGOAPDefinitionAsset.cpp (3), TestGameplayGOAPDefinitionCompiler.cpp (7), портативная проверка tests/tools/run_goap_asset_portable_checks.py — наличие SOURCE_VERIFIED; запуск — audit/validation.md.
