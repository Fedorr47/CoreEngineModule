    04. Цели и контракты действий: выбор цели, применимость, продолжение, стоимость¶

    Коротко

    Цель — набор требуемых булевых фактов с оценкой; выбирается неудовлетворённая цель с наибольшей оценкой (при равенстве — первая по порядку). Действие несёт три разных контракта: предусловия (можно ли начать), эффекты (что модель ожидает после успеха) и условия продолжения (что обязано оставаться истинным, пока шаг выполняется). Стоимость — единственный критерий выбора между планами. Статус: SOURCE_VERIFIED.

    1. Задача и интуиция¶

    Глава 02 описала действие как пару «предусловия — эффекты». Для игры этого мало по двум причинам. Во-первых, целей обычно несколько, и нужно выбрать, над какой работать сейчас. Во-вторых, действие в игре длится: агент бежит к маркеру несколько секунд, и за это время мир меняется. Нужно различать «можно ли начать» и «можно ли продолжать», иначе либо действие прерывается без причины, либо продолжается, когда смысла уже нет.

    2. Теоретическая выкладка¶

    2.1. Выбор цели как argmax с фильтром¶

    Пусть цели G1,…,GmG_1, \dots, G_mG1​,…,Gm​ заданы в порядке определения, у каждой — базовая оценка bkb_kbk​, требуемые факты DkD_kDk​ и (опционально) правила (ckj,δkj)(c_{kj}, \delta_{kj})(ckj​,δkj​): «если условие ckjc_{kj}ckj​ истинно, прибавить δkj\delta_{kj}δkj​». Оценка в состоянии SSS:

    score⁡k(S)=bk+∑jδkj [ ckj(S) ], \operatorname{score}_k(S) = b_k + \sum_j \delta_{kj}\,[\,c_{kj}(S)\,], scorek​(S)=bk​+j∑​δkj​[ckj​(S)],

    где [⋅][\cdot][⋅] — индикатор (1, если истинно). Кандидаты — цели, ещё не выполненные в SSS (¬Dk(S)\neg D_k(S)¬Dk​(S)) и с конечными значениями. Выбор:

    k∗=min⁡{ k:score⁡k=max⁡jscore⁡j }, k^{\ast} = \min\{\,k : \operatorname{score}_k = \max_j \operatorname{score}_j\,\}, k∗=min{k:scorek​=jmax​scorej​},

    то есть максимум оценки, а при равенстве — первая по порядку цель (строгое сравнение score > best, GS-TIE). Если кандидатов нет, «нет цели» — решение считает работу выполненной.

    Это не полноценная функция полезности: правила аддитивны, зависят только от булевых фактов и не учитывают стоимость плана. Связи «выбор цели ↔ стоимость плана» нет: если для выбранной цели плана не существует, менее приоритетные цели не перебираются автоматически SOURCE_VERIFIED.

    2.2. Три контракта действия¶

    Аналогия из планирования с длительными действиями (PDDL 2.1, M. Fox и D. Long, 2003): у durative action есть условия at start, over all и эффекты at end. В CoreEngine:

    Контракт PDDL-аналог Где проверяется Смысл
    preconditions PaP_aPa​ at start поиск; перед стартом шага — весь остаток плана можно начать
    continuationConditions CaC_aCa​ over all каждый update, пока шаг RunningStep основание сохраняется
    effects EaE_aEa​ at end только прогноз (поиск, остаток плана) что ожидаем после успеха

    Правило подмножества. CoreEngine требует Ca⊆PaC_a \subseteq P_aCa​⊆Pa​: каждое условие продолжения должно буквально совпадать с одним из предусловий (для числовых — тот же факт, оператор и значение, PL-CONT-SUBSET). Зачем:

    1. продолжение гарантированно истинно в момент старта (иначе шаг мог бы инвалидироваться сразу после запуска);
    2. автор явно выбирает, какие стартовые основания являются поддерживаемыми («цель доступна»), а какие — расходуемыми («монет ≥ 2», которые покупка сама потратит).

    Почему не проверять все предусловия всё время? Потому что действие может само менять своё основание. Покупка требует coins ≥ 2 и сама списывает 2; агент, бегущий к монете, перестаёт быть atStart. Повторная проверка всех PaP_aPa​ каждый кадр прерывала бы корректное исполнение.

    Формально: шаг aaa, запущенный в момент t0t_0t0​, продолжается в t>t0t > t_0t>t0​, пока Ca(Ot)C_a(O_t)Ca​(Ot​) истинно, где OtO_tOt​ — наблюдаемые факты. В поиске CaC_aCa​ не используется: на входе в действие оно покрыто PaP_aPa​.

    2.3. Стоимость¶

    Стоимость c(a)≥0c(a) \ge 0c(a)≥0 — единица выбора между планами. Смысл единиц задаёт автор: секунды, метры или условные «усилия» — но согласованно для всех действий, которые могут конкурировать. В Access Key стоимости движения заменены длинами путей (метры), а покупка стоит 1 — значит, покупка эквивалентна метру пути; это авторское решение, и его стоит осознавать, когда добавляются альтернативные способы получить ключ.

        [[nodiscard]] float ScoreAIGoal(
        const AIAgentWorldState& worldState,
        const AIGoalSelectionCandidate& candidate) noexcept
    {
        float score = candidate.baseScore;
        for (const AIGoalScoreRule& rule : candidate.scoreRules)
        {
            if (rule.condition.factId.index < AIAgentWorldState::FactCapacity
                && std::isfinite(rule.scoreDelta)
                && AreFactConditionsSatisfied(worldState, std::span{&rule.condition, 1u}))
            {
                score += rule.scoreDelta;
            }
        }
        return score;
    }

    [[nodiscard]] AIGoalSelectionResult SelectAIGoal(
        const AIAgentWorldState& worldState,
        const std::span<const AIGoalSelectionCandidate> candidates) noexcept
    {
        AIGoalSelectionResult selectedGoal{};
        for (const AIGoalSelectionCandidate& candidate : candidates)
        {
            const bool bValidGoal = candidate.goal.goalId.IsValid()
                && std::ranges::all_of(candidate.goal.desiredFacts, [](const AIFactCondition& condition)
                {
                    return condition.factId.index < AIAgentWorldState::FactCapacity;
                });
            if (!bValidGoal || !std::isfinite(candidate.baseScore)
                || AreFactConditionsSatisfied(worldState, candidate.goal.desiredFacts))
            {
                continue;
            }

            const bool bValidRules = std::ranges::all_of(candidate.scoreRules, 
                [](const AIGoalScoreRule& rule)
                {
                    return rule.condition.factId.index < AIAgentWorldState::FactCapacity
                        && std::isfinite(rule.scoreDelta);
                });
            const float score = ScoreAIGoal(worldState, candidate);
            if (!bValidRules || !std::isfinite(score))
            {
                continue;
            }

            if (!selectedGoal.IsValid() || score > selectedGoal.score)
            {
                selectedGoal = AIGoalSelectionResult{
                    .goalId=candidate.goal.goalId,
                    .score=score};
            }
        }
        return selectedGoal;
    }

            [[nodiscard]] bool IsRunningStepContinuationValid_(
            const AIAgentWorldState& observedState,
            const std::span<const AIActionDefinition> actions) const
        {
            if (!execution_.has_value() || !execution_->IsRunningStep())
            {
                return false;
            }

            const AIPlanStep* step = execution_->GetCurrentStep();
            if (step == nullptr)
            {
                return false;
            }
            const auto definition = std::ranges::find_if(actions,
                [&](const AIActionDefinition& action)
                {
                    return action.actionId == step->actionId
                        && action.contextId == step->contextId;
                });
            return definition != actions.end()
                && AreFactConditionsSatisfied(
                    observedState, definition->continuationConditions)
                && AreNumericConditionsSatisfied(
                    observedState, definition->numericContinuationConditions);
        }

            [[nodiscard]] bool IsRemainingPlanValid_(
            const AIAgentWorldState& observedState,
            const AIGoalDefinition& goal,
            const std::span<const AIActionDefinition> actions) const
        {
            if (!execution_.has_value())
            {
                return false;
            }

            AIAgentWorldState predicted = observedState;
            const AIPlan& plan = execution_->GetPlan();
            for (std::size_t index = execution_->GetCurrentStepIndex();
                index < plan.steps.size(); ++index)
            {
                const AIPlanStep& step = plan.steps[index];
                const auto definition = std::ranges::find_if(actions,
                    [&](const AIActionDefinition& action)
                    {
                        return action.actionId == step.actionId
                            && action.contextId == step.contextId;
                    });
                if (definition == actions.end()
                    || !AreFactConditionsSatisfied(predicted, definition->preconditions)
                    || !AreNumericConditionsSatisfied(predicted, definition->numericPreconditions))
                {
                    return false;
                }

                ApplyFactEffects(predicted, definition->effects);
                if (!ApplyNumericEffects(predicted, definition->numericEffects))
                {
                    return false;
                }
            }

            return AreFactConditionsSatisfied(predicted, goal.desiredFacts);
        }

    Это «мини-поиск без ветвления»: остаток плана прогоняется по текущим фактам с применением эффектов к копии, и в конце проверяется цель. Если предыдущий шаг удался, но наблюдение ещё не подтвердило его эффект, проверка не пройдёт и решение будет перепланировать (глава 08).

    4.4. Где проверяется правило подмножества¶

    Компилятор определения и template правило Ca⊆PaC_a \subseteq P_aCa​⊆Pa​ не проверяют; его проверяет IsInputValid планировщика (PL-INPUT). Нарушение даёт nullopt при каждом поиске INFERRED (см. главу 05 §4.1).

    5. Разобранный пример¶

    Marker Visit (AS-MARKER-GOAP). Действие move_to/visitMarker: P={P = \{P={markerPresent = true}\}}, E={E = \{E={markerReached = true}\}}, C={C = \{C={markerPresent = true}\}} ⊆ PPP ✓, стоимость 2. Пока агент бежит, маркер должен оставаться доступным; если его InteractionPoint исчезнет, шаг будет прерван.

    Access Key (AS-ACCESS-BUY). У purchase/buy_key P={P = \{P={hasAccessKey = false, atAccessKeyShop = true, coins ≥ 2}\}}, E={E = \{E={hasAccessKey = true, coins += −2}\}}, C=∅C = \varnothingC=∅. Продолжения нет: покупка мгновенна (Start сразу возвращает Succeeded, глава 17), а основание coins ≥ 2 — расходуемое.

    Выбор цели (учебный пример). Две цели в порядке определения: patrol (b=1b = 1b=1) и flee (b=1b = 1b=1) с правилом threatSeen = true → +5. При threatSeen = false: оценки 111 и 111 → выбирается patrol (первая при равенстве). При threatSeen = true: 111 и 666 → flee. Если flee уже выполнена (safe = true — её desiredFacts), она исключается до оценки, и выбор возвращается к patrol. Такое правило нельзя записать в .goap.json — только кодом.

    6. Типичные ошибки, границы и проверка¶

    • Ожидать перебора целей. Если для выбранной цели плана нет, решение Failed, другая цель не пробуется.
    • Равные score. Порядок целей в файле — часть поведения.
    • Continuation вне preconditions. Нет ошибки загрузки, но планов не будет никогда.
    • Расходуемое основание в continuation. Шаг прервёт сам себя, как только начнёт достигать цели.
    • Эффект, который нельзя наблюдать. Цель будет «вечно» перепланироваться после успешного шага.
    • Несогласованные единицы стоимости. Оптимальный по числу план окажется не тем, что ожидал автор.
