    15. Obstacle avoidance: feelers, escape-направление, опора и память стороны¶

    Коротко

    Avoidance корректирует уже выбранное намерение движения. Три геометрических запроса (forward и два боковых feeler под ±30°) проверяют просвет сферой радиуса персонажа; при препятствии впереди строятся два escape-кандидата (смесь направления feeler, касательной к поверхности и отталкивания от неё), для каждого проверяется опора под будущей позицией, и выбирается сторона: опора важнее просвета, а сохранённая сторона меняется только при заметном преимуществе другой. Механизм локален: он не ищет путь и не видит динамических объектов при стандартном физическом query. Статус: SOURCE_VERIFIED.

    1. Задача и интуиция¶

    Маршрут из авторского графа или прямой Seek не знают о ящике посреди пути. Нужна реактивная поправка: увидеть препятствие впереди, отвернуть в сторону, где свободно и есть куда поставить ногу, и не метаться между сторонами каждый кадр. Это классическое «obstacle avoidance» из steering-поведений Reynolds, но в CoreEngine с двумя практическими добавками: проверкой опоры (не уйти с обрыва при обходе) и памятью стороны.

    2. Теоретическая выкладка¶

    2.1. Пробы как sweep сферы¶

    Чтобы проверить, пройдёт ли тело радиуса rrr, достаточно провести сферу радиуса re=r+mr_e = r + mre​=r+m (mmm — запас, 0.02 м) вдоль луча: попадание сферы эквивалентно попаданию точечного луча в препятствие, «раздутое» на rer_ere​ (сумма Минковского). Результат — дистанция до первого контакта (clearance) и нормаль поверхности (OA-PHYS-PROBE).

    Дальность переднего пробы растёт со скоростью, чтобы времени на реакцию хватало при беге:

    Lf=max⁡ ⁣(L0,  v⋅τ),L0=3 м,  τ=0.75 с, L_f = \max\!\big(L_0,\; v \cdot \tau\big), \qquad L_0 = 3\ \text{м},\; \tau = 0.75\ \text{с}, Lf​=max(L0​,v⋅τ),L0​=3 м,τ=0.75 с,

    где vvv — фактическая горизонтальная скорость мотора. При ходьбе (v≤2v \le 2v≤2) Lf=3L_f = 3Lf​=3, при беге 4.5 м/с — 3.3753.3753.375, при 6 м/с — 4.54.54.5 (OA-SANITIZE).

    2.2. Боковые feelers¶

    Для единичного направления движения f^=(fx,fz)\hat f = (f_x, f_z)f^​=(fx​,fz​) и угла θ\thetaθ (30°):

    ℓ^=(fxcos⁡θ+fzsin⁡θ,  fzcos⁡θ−fxsin⁡θ),r^=(fxcos⁡θ−fzsin⁡θ,  fzcos⁡θ+fxsin⁡θ). \hat\ell = (f_x\cos\theta + f_z\sin\theta,\; f_z\cos\theta - f_x\sin\theta), \qquad \hat r = (f_x\cos\theta - f_z\sin\theta,\; f_z\cos\theta + f_x\sin\theta). ℓ^=(fx​cosθ+fz​sinθ,fz​cosθ−fx​sinθ),r^=(fx​cosθ−fz​sinθ,fz​cosθ+fx​sinθ).

    В правосторонней системе с +Y+Y+Y вверх для f^=(1,0)\hat f = (1, 0)f^​=(1,0) получаем ℓ^=(0.866,−0.5)\hat\ell = (0.866, -0.5)ℓ^=(0.866,−0.5) — к −Z-Z−Z, то есть налево от направления движения, r^\hat rr^ — направо (OA-FEELERS). Дальность боковых проб — 2 м. Все три пробы вычисляются до ветвления: их результаты нужны и для выбора стороны, и для отладки.

    2.3. Escape-направление¶

    Если передняя проба попала (нормаль n\mathbf nn), для каждой стороны строится кандидат

    e^side=norm⁡(0.60 s^side+0.40 t^side+0.30 n^xz), \hat e_{\text{side}} = \operatorname{norm}\big(0.60\,\hat s_{\text{side}} + 0.40\,\hat t_{\text{side}} + 0.30\,\hat n_{xz}\big), e^side​=norm(0.60s^side​+0.40t^side​+0.30n^xz​),

    где s^\hat ss^ — боковой feeler, n^xz\hat n_{xz}n^xz​ — горизонтальная проекция нормали, t^\hat tt^ — касательная к поверхности в XZ, ориентированная в сторону обхода. Смысл слагаемых: feeler сохраняет прогресс вперёд и вбок, касательная задаёт скольжение вдоль стены, нормаль отталкивает от неё. Веса не вероятности и не обязаны давать 1 — результат нормируется (OA-WEIGHTS).

    Ориентация касательной. Из n^xz=(nx,nz)\hat n_{xz} = (n_x, n_z)n^xz​=(nx​,nz​) две касательные: ±(−nz,nx)\pm(-n_z, n_x)±(−nz​,nx​). Знак выбирается относительно стабильной оси «вправо» a^=(−fz,fx)\hat a = (-f_z, f_x)a^=(−fz​,fx​): правая касательная — та, у которой t^⋅a^≥0\hat t\cdot\hat a \ge 0t^⋅a^≥0; левая — противоположная. Если согласовывать знак с вращающимся feeler, при t^⋅s^≈0\hat t\cdot\hat s \approx 0t^⋅s^≈0 знак мог бы перескакивать и выбранная сторона внезапно меняла бы фактическое направление (комментарий в OA-ESCAPE).

    2.4. Опора: проверка будущей позиции¶

    Широкий просвет сбоку не гарантирует пол. Для каждого e^\hat ee^ выполняется луч вниз из точки

    o=b+e^ ds+y^ hs,длина ℓ=hs+ddrop, \mathbf o = \mathbf b + \hat e\, d_s + \hat y\, h_s, \qquad \text{длина } \ell = h_s + d_{\text{drop}}, o=b+e^ds​+y^​hs​,длина ℓ=hs​+ddrop​,

    где b\mathbf bb — основание персонажа, ds=0.75d_s = 0.75ds​=0.75 — вынос вперёд, hs=0.25h_s = 0.25hs​=0.25 — подъём начала луча, ddrop=0.35d_{\text{drop}} = 0.35ddrop​=0.35 — допустимое падение; ℓ=0.60\ell = 0.60ℓ=0.60 (OA-SUPPORT). Попадание принимается, если дистанция конечна и ≤ℓ\le \ell≤ℓ, а нормаль конечна. При включённой проверке уклона нормаль нормируется и

    n^⋅y^≥cos⁡θmax⁡−ε2, \hat n\cdot\hat y \ge \cos\theta_{\max} - \varepsilon^2 , n^⋅y^​≥cosθmax​−ε2,

    потому что угол поверхности с горизонтом равен углу её нормали с вертикалью. Для θmax⁡=45°\theta_{\max} = 45°θmax​=45° порог ≈0.70711\approx 0.70711≈0.70711; нормаль (0,1,0)(0, 1, 0)(0,1,0) проходит.

    2.5. Выбор стороны с памятью¶

    Пусть cL,cRc_L, c_RcL​,cR​ — clearance боковых проб, aL,aRa_L, a_RaL​,aR​ — наличие опоры, mmm — сохранённая сторона, δ=0.15\delta = 0.15δ=0.15:

    1. ¬aL∧¬aR\neg a_L \wedge \neg a_R¬aL​∧¬aR​ → нулевая команда, m←Nonem \leftarrow \text{None}m←None (безопаснее стоять, чем шагнуть в пустоту);
    2. aL≠aRa_L \ne a_RaL​=aR​ → сторона с опорой, даже против mmm;
    3. обе с опорой: при m=Nonem = \text{None}m=None — левая, если cL≥cRc_L \ge c_RcL​≥cR​ (равенство → левая, детерминизм); при m=Leftm = \text{Left}m=Left смена на правую только если cR>cL+δc_R > c_L + \deltacR​>cL​+δ; симметрично для m=Rightm = \text{Right}m=Right.

    Это гистерезис той же природы, что у Flee (глава 14): без памяти шум clearance менял бы сторону каждый кадр. Если впереди свободно, команда не меняется и память сбрасывается (OA-SIDE).

    2.6. Границы механизма¶

    Avoidance — локальная поправка за один кадр. Он не гарантирует выхода из тупика (обе стороны с опорой, но путь замкнут), не перестраивает маршрут, не согласует встречные потоки агентов (не ORCA/RVO) и при стандартном query видит только StaticWorld — других агентов и динамические тела не видит (OA-PHYS-QUERY). Проверка опоры выполняется только при обходе препятствия; при свободном пути движение к краю не проверяется — это не «защита от обрыва» в общем смысле. Физический контроллер остаётся последней инстанцией.

    rendern::GameplayMovementIntent rendern::ApplyGameplayObstacleAvoidance(
    const GameplayObstacleAvoidanceInput& input,
    const IGameplayObstacleQuery& query,
    const GameplayObstacleAvoidanceSettings& settings,
    GameplayObstacleAvoidanceState& state,
    GameplayObstacleAvoidanceDebugSnapshot* debugOut) noexcept
{
    const GameplayMovementIntent& baseMovement = input.baseMovement;
    const mathUtils::Vec3& probeOrigin = input.probeOrigin;
    if (debugOut != nullptr)
    {
        *debugOut = {};
        debugOut->evaluated = true;
        debugOut->probeOrigin = probeOrigin;
        debugOut->baseMovement = baseMovement;
        debugOut->finalMovement = baseMovement;
    }
    if (!baseMovement.IsMoving())
    {
        state.committedSide = GameplayObstacleAvoidanceSide::None;
        return baseMovement;
    }

    mathUtils::Vec3 forward{baseMovement.moveWorld.x, 0.0f, baseMovement.moveWorld.z};
    const float forwardLengthSquared = mathUtils::Dot(forward, forward);
    if (!mathUtils::IsFinite(forward) || forwardLengthSquared <= mathUtils::kLengthEpsilonSq)
    {
        state.committedSide = GameplayObstacleAvoidanceSide::None;
        return baseMovement;
    }
    forward = forward / std::sqrt(forwardLengthSquared);

    const SanitizedSettings sanitized = Sanitize(input, settings);
    const float cosine = std::cos(sanitized.sideAngleRadians);
    const float sine = std::sin(sanitized.sideAngleRadians);

    const mathUtils::Vec3 left{
        (forward.x * cosine) + (forward.z * sine),
        0.0f,
        (forward.z * cosine) - (forward.x * sine)
    };
    const mathUtils::Vec3 right{
        (forward.x * cosine) - (forward.z * sine),
        0.0f,
        (forward.z * cosine) + (forward.x * sine)
    };

    const ProbeResult forwardResult = RunProbe(
        query, probeOrigin, forward, sanitized.forwardDistance,
        sanitized.effectiveClearanceRadius,
        debugOut != nullptr ? &debugOut->forward : nullptr);
    const ProbeResult leftResult = RunProbe(
        query, probeOrigin, left, sanitized.sideDistance,
        sanitized.effectiveClearanceRadius,
        debugOut != nullptr ? &debugOut->left : nullptr);
    const ProbeResult rightResult = RunProbe(
        query, probeOrigin, right, sanitized.sideDistance,
        sanitized.effectiveClearanceRadius,
        debugOut != nullptr ? &debugOut->right : nullptr);

    if (!forwardResult.hit)
    {
        state.committedSide = GameplayObstacleAvoidanceSide::None;
        return baseMovement;
    }

    GameplayMovementIntent corrected = baseMovement;
    const mathUtils::Vec3 leftEscape = BuildEscapeCandidate(
        left,
        forward,
        GameplayObstacleAvoidanceSide::Left,
        forwardResult.hitNormal);
    const mathUtils::Vec3 rightEscape = BuildEscapeCandidate(
        right,
        forward,
        GameplayObstacleAvoidanceSide::Right,
        forwardResult.hitNormal);
    const bool leftSupported = HasSupport(query, probeOrigin, leftEscape, sanitized);
    const bool rightSupported = HasSupport(query, probeOrigin, rightEscape, sanitized);
    if (debugOut != nullptr)
    {
        debugOut->leftSupported = leftSupported;
        debugOut->rightSupported = rightSupported;
        debugOut->leftEscapeCandidate = leftEscape;
        debugOut->rightEscapeCandidate = rightEscape;
    }
    if (!leftSupported && !rightSupported)
    {
        state.committedSide = GameplayObstacleAvoidanceSide::None;
        corrected.moveWorld = {};
        corrected.moveMagnitude = 0.0f;
        if (debugOut != nullptr)
        {
            debugOut->active = true;
            debugOut->finalMovement = corrected;
        }
        return corrected;
    }

    // Equal clearance always selects left, keeping symmetric situations deterministic.
    const GameplayObstacleAvoidanceSide preferredSide =
        leftResult.clearance >= rightResult.clearance
        ? GameplayObstacleAvoidanceSide::Left
        : GameplayObstacleAvoidanceSide::Right;
    GameplayObstacleAvoidanceSide chosenSide = preferredSide;
    const GameplayObstacleAvoidanceSide previousSide = state.committedSide;
    if (leftSupported != rightSupported)
    {
        chosenSide = leftSupported
            ? GameplayObstacleAvoidanceSide::Left
            : GameplayObstacleAvoidanceSide::Right;
    }
    else if (state.committedSide == GameplayObstacleAvoidanceSide::Left)
    {
        chosenSide = rightResult.clearance > leftResult.clearance +
                sanitized.sideSwitchClearanceAdvantage
            ? GameplayObstacleAvoidanceSide::Right
            : GameplayObstacleAvoidanceSide::Left;
    }
    else if (state.committedSide == GameplayObstacleAvoidanceSide::Right)
    {
        chosenSide = leftResult.clearance > rightResult.clearance +
                sanitized.sideSwitchClearanceAdvantage
            ? GameplayObstacleAvoidanceSide::Left
            : GameplayObstacleAvoidanceSide::Right;
    }
    state.committedSide = chosenSide;
    const bool preferredUnsupported =
        (preferredSide == GameplayObstacleAvoidanceSide::Left && !leftSupported) ||
        (preferredSide == GameplayObstacleAvoidanceSide::Right && !rightSupported);
    const bool committedUnsupported =
        (previousSide == GameplayObstacleAvoidanceSide::Left && !leftSupported) ||
        (previousSide == GameplayObstacleAvoidanceSide::Right && !rightSupported);
    const bool safetyOverride = leftSupported != rightSupported &&
        (preferredUnsupported || committedUnsupported);
    const bool choseLeft = chosenSide == GameplayObstacleAvoidanceSide::Left;
    corrected.moveWorld = choseLeft ? leftEscape : rightEscape;
    if (debugOut != nullptr)
    {
        const float directionDot = mathUtils::Dot(forward, corrected.moveWorld);
        const bool changedDirection = std::isfinite(directionDot) &&
            directionDot < 1.0f - mathUtils::kLengthEpsilonSq;
        debugOut->active = changedDirection;
        debugOut->preferredSide = changedDirection
            ? preferredSide
            : GameplayObstacleAvoidanceSide::None;
        debugOut->chosenSide = changedDirection
            ? chosenSide
            : GameplayObstacleAvoidanceSide::None;
        debugOut->sideHeldByHysteresis = changedDirection && !safetyOverride &&
            leftSupported && rightSupported &&
            previousSide != GameplayObstacleAvoidanceSide::None &&
            chosenSide == previousSide && chosenSide != preferredSide;
        debugOut->safetyOverride = safetyOverride;
        debugOut->finalMovement = corrected;
    }
    return corrected;
}

        [[nodiscard]] GameplayMovementIntent ApplyGameplayAgentObstacleAvoidance(
        const GameplayWorld& world,
        const EntityHandle entity,
        const GameplayMovementIntent& baseMovement,
        const IGameplayObstacleQuery& query,
        const GameplayObstacleAvoidanceSettings& settings,
        GameplayObstacleAvoidanceState& state,
        GameplayObstacleAvoidanceDebugSnapshot* debugOut = nullptr) noexcept
    {
        const GameplayTransformComponent* transform = world.TryGetTransform(entity);
        const GameplayCharacterPhysicalSettingsComponent* physical =
            world.TryGetCharacterPhysicalSettings(entity);
        const GameplayCharacterMotorComponent* motor = world.TryGetCharacterMotor(entity);
        if (transform == nullptr || physical == nullptr || motor == nullptr)
        {
            return baseMovement;
        }

        const float supportOriginVerticalOffset = physical->GetTotalHeight() * 0.5f;
        const mathUtils::Vec3 probeOrigin = transform->position +
            mathUtils::Vec3{0.0f, supportOriginVerticalOffset, 0.0f};
        const mathUtils::Vec3 planarVelocity{
            motor->velocity.x, 0.0f, motor->velocity.z};
        const GameplayObstacleAvoidanceInput input{
            .baseMovement = baseMovement,
            .probeOrigin = probeOrigin,
            .characterRadius = physical->radius,
            .supportOriginVerticalOffset = supportOriginVerticalOffset,
            .currentPlanarSpeed = mathUtils::Length(planarVelocity),
            .maximumWalkableSlopeAngleDegrees = physical->maximumSlopeAngleDegrees
        };
        return ApplyGameplayObstacleAvoidance(input, query, settings, state, debugOut);
    }

    6. Типичные ошибки, границы и проверка¶

    • Ожидать avoidance у ассетного GOAP-агента. Query не передаётся (глава 09).
    • Ожидать, что avoidance видит других агентов. Маска StaticWorld.
    • Считать support «защитой от обрыва». Проверка только у кандидатов обхода; свободный путь к краю не проверяется.
    • Свой query без ProbeSupport. Синтетическая опора — любой обрыв «проходим».
    • Тупик. Обе стороны с опорой, но выхода нет: агент будет скользить вдоль стены; нужна перестройка маршрута.
    • Дрожание стороны. Должно подавляться порогом 0.15; если нет — смотрите clearance в steering debug (глава 19).
