    09. Исполнение и lifetime: bridge, bindings, AISystem и владение¶

    Коротко

    Семантический шаг плана (actionId, contextId) становится исполняемым через binding: он создаёт runtime (IAIActionRuntime), который AISystem помещает в AIActionTask — одну задачу на агента. Задачи стартуют синхронно и тикают в aiSystem_.Update. Instance решения владеет контекстом, провайдерами, bindings и буферами событий; bindings и runtimes заимствуют их ссылки, поэтому порядок уничтожения и порядок отмены — часть контракта. Статус: SOURCE_VERIFIED.

    1. Задача и интуиция¶

    План говорит «move_to в контексте start_to_coin_c», но не знает, что это значит в мире: какой маршрут, какие радиусы, нужна ли бронь. Нужен механизм позднего связывания «семантика → исполнитель» и объект, который живёт, пока шаг выполняется, и умеет корректно остановиться. Эта глава объясняет цепочку объектов и правила их жизни.

    2. Теоретическая выкладка¶

    2.1. Разделение «что» и «как»: binding как фабрика¶

    Шаг плана — команда в символическом языке. Binding — фабрика, переводящая команду и контекст агента в конкретный объект исполнения:

    bindingactionId:(agent,actionId,contextId)  ↦  runtime  ∣  ∅. \text{binding}_{\text{actionId}} : (\text{agent}, \text{actionId}, \text{contextId}) \;\mapsto\; \text{runtime} \;|\; \varnothing . bindingactionId​:(agent,actionId,contextId)↦runtime∣∅.

    Один binding обслуживает все контексты своего семантического действия: MoveToActionBinding по contextId находит маршрут конкретного контекста. Реестр bindings ключуется только actionId (AB-REGISTRY). Плюс подхода: планировщику и исполнению не нужно знать о маршрутах, бронях и покупках; минус — ошибка связывания проявляется только при старте шага (binding вернул nullptr → шаг Failed).

    2.2. Интерфейс runtime как протокол¶

    IAIActionRuntime задаёт протокол из трёх вызовов (AR-IFACE):

    • Start(context) → Running | Succeeded | Failed — однократно;
    • Tick(context, dt) → то же — только после Running;
    • Cancel(context) — явная граница прерывания и очистки, не применяет эффектов планировщика.

    Владелец протокола — AIActionTask: он гарантирует порядок (Tick не вызывается до успешного Start, Cancel — только в Running) и хранит статус (AT-CLASS). Runtime может быть «мгновенным» (покупка: Start → Succeeded) или «длительным» (движение: Start → Running, затем серия Tick).

    2.3. Одна задача на агента¶

    AISystem хранит unordered_map<EntityHandle, AIActionTask>: у агента не более одной задачи. StartAction отменяет и удаляет прежнюю задачу, затем создаёт новую и сразу вызывает Start (AS-START). Terminal-задача остаётся в карте, пока её не заменят или агент не перестанет быть AI-сущностью — именно поэтому решение может прочитать Succeeded при следующей синхронизации (AS-CLEANUP).

    2.4. Время жизни и заимствование¶

    Правило безопасности ссылок: объект может хранить ссылку только на объект, который гарантированно живёт дольше. В instance решения это обеспечено порядком полей: члены уничтожаются в обратном порядке объявления, а goap_ (с bindings) объявлен последним — значит, уничтожается первым, раньше контекста с провайдерами и буферов событий (GG-FIELD-ORDER). Копирование и перемещение instance запрещены, чтобы адреса фактов и буферов, которые bindings получили при создании, не менялись.

    Runtimes в AISystem тоже заимствуют: покупка — факты и буфер событий instance, движение — мир, реестры traversal, query. Поэтому владелец решения обязан отменить задачу до уничтожения instance. GameplayRuntime делает это во всех путях: CancelAIDecision, CancelAllAIDecisions_, переход в Editor, Shutdown (GR-CANCEL-DECISION, GR-MODE-EDITOR).

            std::size_t Update(GameplayWorld& world, const float deltaSeconds = 0.0f)
        {
            world.CollectAIEntities(aiEntitiesScratch_);
            CleanupInactiveTasks_(world);

            for (const EntityHandle entity : aiEntitiesScratch_)
            {
                auto taskIt = tasksByEntity_.find(entity);
                if (taskIt == tasksByEntity_.end())
                {
                    continue;
                }

                AIActionTask& task = taskIt->second;
                if (task.GetStatus() == AIActionExecutionStatus::NotStarted)
                {
                    [[maybe_unused]] const AIActionExecutionStatus status = task.Start();
                }
                if (task.IsRunning())
                {
                    [[maybe_unused]] const AIActionExecutionStatus status =
                        task.Tick(deltaSeconds);
                }
            }

            return aiEntitiesScratch_.size();
        }

        [[nodiscard]] AIActionExecutionStatus StartAction(
            const GameplayWorld& world,
            const AIActionRuntimeContext context,
            std::unique_ptr<IAIActionRuntime> runtime)
        {
            const bool bHasValidContext = context.IsValid();
            const bool bHasRuntime = runtime != nullptr;
            const bool bHasValidEntity = bHasValidContext && world.IsEntityValid(context.agentEntity);
            const bool bIsAIAgent = bHasValidEntity && world.HasAI(context.agentEntity);

            if (!bHasValidContext || !bHasRuntime || !bHasValidEntity || !bIsAIAgent)
            {
                return AIActionExecutionStatus::Failed;
            }

            CancelAction(context.agentEntity);
            tasksByEntity_.erase(context.agentEntity);
            auto taskEntry = tasksByEntity_.emplace(
                context.agentEntity,
                AIActionTask(context, std::move(runtime)));

            return taskEntry.first->second.Start();
        }

        [[nodiscard]] std::unique_ptr<IAIActionRuntime> CreateRuntime(
            const AIActionRuntimeContext& context) override
        {
            if (context.actionId != kAIMoveToActionId)
            {
                return nullptr;
            }
            const std::optional<AIMoveToActionRequest> request =
                requestProvider_.ResolveRequest(context);
            if (!request)
            {
                return nullptr;
            }
            if (reservationSystem_ != nullptr && reservationTargetProvider_ != nullptr)
            {
                const EntityHandle target = reservationTargetProvider_->ResolveReservationTarget(context);

                }

            return AIMoveToAction::CreateRuntime(
                context,
                world_,
                traversalLinkRegistry_,
                traversalExecutorRegistry_,
                *request,
                obstacleQuery_, {}, debugRegistry_, navigationDebugRegistry_);
        }

    5. Разобранный пример: жизнь шага buy_key и шага move_to¶

    buy_key (мгновенный). Решение в ReadyToStartStep вызывает мост → реестр находит PurchaseBinding → он по contextId выбирает транзакцию receipt unlock и создаёт PurchaseRuntime, заимствующий факты и runtimeEvents_ instance → AISystem::StartAction отменяет предыдущую (уже Succeeded) задачу движения, создаёт новую и вызывает Start → покупка проверяет условия и пишет событие → Succeeded → мост сразу продвигает план к следующему шагу (ReadyToStartStep). В том же update instance делает второй проход наблюдения и подтверждает покупку (глава 07).

    access_key_shop_to_goal (длительный). На следующем update шаг стартует: MoveToCapability::ResolveRequest проверяет sourceRadius = 0.6 (ближайший узел графа к агенту — shop, дистанция ≤ 0.6) и возвращает указатель на граф (живёт в провайдере) и узлы → AIMoveToAction::CreateRuntime ищет путь (Дейкстра) и передаёт копию маршрута во владение AIFollowRouteActionRuntime → Start публикует маршрут в navigation debug (здесь — nullptr, публикации нет) и запускает follower → Running; aiSystem_.Update того же кадра делает первый Tick.

    Отмена. Сценарий вызывает cancelAIDecision: GameplayRuntime::CancelAIDecision → Cancel решения → CancelPlanExecution → AISystem::CancelAction → AIActionTask::Cancel → AIFollowRouteActionRuntime::Cancel (отмена traversal, обнуление команды и горизонтальной скорости, очистка debug) → instance удаляется из карты. Задача со статусом Cancelled остаётся в AISystem до следующего StartAction или ClearAIAction.

    6. Типичные ошибки, границы и проверка¶

    • Два источника задач на одного агента. Прямой StartAI* заменит задачу решения (и наоборот).
    • Уничтожить instance без отмены. Runtime с заимствованными ссылками останется в AISystem — висячие ссылки. Используйте API GameplayRuntime, которые отменяют задачи.
    • Ожидать avoidance у ассетного GOAP. Query не передаётся; агент полагается на физический контроллер и авторский граф.
    • Ожидать удаления terminal-задачи. Она остаётся до замены; GetAIActionStatus вернёт её статус.
    • Graph-указатель запроса. AIMoveToActionRequest::routeGraph невладеющий и действителен только во время создания runtime; маршрут runtime копирует.

    Проверки: TestAISystem.cpp (13), TestAIActionTask.cpp (12), TestAIActionBinding.cpp (2), TestAIMoveToActionBinding.cpp (10), TestAIPlanExecutionBridge.cpp (6) — наличие SOURCE_VERIFIED.
