# CoreEngine: от теории к коду

Каждый тематический раздел самодостаточен: собственная теория, затем возврат к текущей реализации.
Общая вводная глава не заменяет теорию раздела.

## Обязательная структура главы (`docs/AIAtlas/docs/chapters/NN-*.md`)

1. `## 1. Задача и интуиция` — какой вопрос решает механизм; термины человеческим языком; связь с предыдущей
   главой и зачем нужен следующий слой.
2. `## 2. Теоретическая выкладка` — по шагам. Для алгоритмов/геометрии — вывод формул; для архитектуры — модель
   данных, граф зависимостей, ownership/lifetime, state machine, инварианты. Ориентир для крупной темы — 2–3
   страницы связного текста (валидатор требует ≥ 250 слов в этом разделе).
3. `## 3. Визуальное объяснение` — схема/график (`@@diagram id | подпись`) и абзац «что заметить».
4. `## 4. Как это реализовано в CoreEngine` — типы/функции, входы/выходы, изменяемое состояние, caller/callee,
   частота, ownership, ошибки; короткие выдержки `@@code REF-ID N`; ссылки `[[REF-ID]]`; карточки `[[cls:Name]]`.
5. `## 5. Разобранный пример` — от входа до результата: значения фактов до/после, шаги очереди, порядок событий,
   численный расчёт. Реальные числа (ассеты, код) отделять от учебных.
6. `## 6. Типичные ошибки, границы и проверка` — ошибки, проверенные ограничения, тесты/диагностика, переход дальше.

## Правила для формул

Для каждой важной формулы: решаемая задача; все обозначения и единицы; предпосылки; вывод или обоснование формы;
численная подстановка; интерпретация; особые случаи (нулевые векторы, совпадающие пороги, вырожденные интервалы);
связь с кодом (какая переменная = какой символ). Указывать систему координат (правосторонняя, +Y вверх; steering
в XZ), знаки и нормировку. Блочная формула — отдельный абзац `$$ … $$` (внутри списка — с отступом 4 пробела
и пустыми строками вокруг).

## Правила честности

- Внешняя теория (STRIPS, A*, Reynolds, Detour) отделена от «как сейчас в CoreEngine». Не называть
  uniform-cost search «A*», magnitude — «силой».
- Псевдокод помечать как псевдокод и давать путь к реализации.
- Каждый численный пример добавлять в `docs/AIAtlas/tools/verify_examples.py` с ожидаемым значением, выведенным
  вручную; учебные модели — `tools/atlas_models.py`, `tools/goap_model.py`.
- Статусы `[[SV]] [[EV]] [[INF]] [[HIST]] [[PROP]] [[NV]]` ставить там, где утверждение могло бы быть принято за
  проверенное поведение.

## Ревью главы — быстрый чеклист

- Есть ли вывод, а не только готовая формула? Объяснены ли все символы и единицы?
- Совпадает ли каждое соответствие «символ ↔ переменная» с выдержкой кода?
- Есть ли хотя бы один реальный пример из ассетов/кода и пересчитан ли он?
- Нет ли выдуманного вызывающего (каждый caller подтверждён записью реестра)?
- Указаны ли границы и что именно НЕ гарантируется?
