# Контрольные вопросы аудита AI CoreEngine

Отвечать по коду; для каждого ответа — статус и якорь реестра.

## Состояние и планирование
- Представление фактов (типы, ёмкость, ID), равенство, хеш, поведение при невалидном индексе.
- Алгоритм поиска (uniform-cost / A* / иное), tie-breaking, дубликаты, лимиты, стоимость копирования узла.
- Где проверяется контракт continuation ⊆ preconditions (компилятор, template, планировщик?).
- Как выбирается цель; что при равных score; есть ли перебор менее приоритетных целей.

## Решение и исполнение
- Ветви `AIDecisionRuntime::Update`: sync шага, нет цели, смена цели, invalidation, поиск до отмены, установка плана.
- Failed / explicit Cancel / retained instance / удаление instance; поведение первого неуспешного старта.
- Кто владеет runtime действия, bindings, providers, контекстом; порядок уничтожения.
- В каком кадре стартует следующий шаг после успеха предыдущего.

## Композиция и ассеты
- Стадии: parse → compile → template → instance; что проверяется на каждой; транзакционность регистрации.
- Роли: снимок позиции/handle или живая привязка.
- Какие сервисы передаются в bindings при ассетной композиции и при прямом запуске (obstacle query, debug).

## Наблюдения и события
- Writers фактов, порядок зависимостей, ObserveActionEvents, порядок проходов событий в одном update.
- Подтверждение событий (ledger, receipts) против предсказанных эффектов; брони и сбор pickup.

## Движение
- Источники маршрутов (авторский граф, NavMesh, fallback), где route cost попадает в GOAP.
- Follower: arrival промежуточных/финального сегментов, look-ahead, плоскость перехода, traversal handoff.
- Steering: формулы, плоскость, единицы, команда против скорости/силы.
- Follow/Flee: sampling, переиздание команды, гистерезис. Avoidance: probes, escape, опора, память стороны.
- `physicallyBlocked`: как вычисляется, кто читает, есть ли recovery.
- Порядок кадра App → GameplayRuntime → AISystem → физика → post-physics; где видна обратная связь.
