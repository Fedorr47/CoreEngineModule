# CoreEngine: аудит исходников для документации

Цель — утверждения о поведении, которые можно доказать строкой текущего кода, и честная граница там, где
доказательства нет. Результат аудита пишется на диск (`docs/AIAtlas/audit/`), чтобы не повторять его после смены
контекста.

## Входы

- Рабочее дерево репозитория (единственный источник истины), правила `CLAUDE.md`, `AGENTS.md`, `tests/README.md`.
- Старая документация — только как список вопросов для перепроверки.
- Навигация: `docs/refactor/index/subsystems/*.md` (генерируемая, не авторитетная).

## Порядок

1. **Снимок.** `git rev-parse --show-toplevel`, ветка, HEAD, `git status --short`, дата. Не переключать ветку, не
   делать reset/stash/clean. Если HEAD отстаёт от remote или снимок старой документации не является предком HEAD —
   остановиться и спросить пользователя, какой снимок описывать (`git merge-base --is-ancestor`).
2. **Карта.** Перечислить файлы домена с размерами (`wc -l`), выделить: контракты, реализации, фабрики/реестры,
   места композиции, публичные точки входа, порядок кадра, ассеты, тесты, сценарии.
3. **Чтение.** Читать объявления **и** реализации **и** места вызова. Для каждого утверждения найти: где создаётся,
   кто вызывает, в какой фазе кадра, кто владеет, что делает при ошибке. Учитывать `.cppm`, `.cpp`, `.h`, `.inl`.
4. **Запреты на вывод по имени.** Не определять алгоритм по имени файла, связь — по похожим именам, наследование —
   по суффиксу. Каждая стрелка «A вызывает B» — это найденная строка вызова.
5. **Статусы.** `SOURCE_VERIFIED` (прочитано), `EVIDENCE_VERIFIED` (есть запуск с датой/ревизией/окружением),
   `INFERRED` (вывод + основание), `HISTORICAL`, `PROPOSED`, `NOT_VERIFIED`. Наличие тестового файла ≠ запуск.
6. **Delta.** Для старой документации: утверждение → `CONFIRMED` / `CHANGED` / `REMOVED` / `NOT_VERIFIED` →
   текущий источник → раздел новой документации. Сначала проверить `git diff <old> HEAD -- <пути домена>`:
   пустой diff означает, что расхождения — ошибки старого документа, а не эволюция кода.
7. **Реестр.** Каждое существенное утверждение получает запись в `docs/AIAtlas/tools/references.py`:
   `(ID, путь, уникальный текст строки-якоря, n-е вхождение, описание)`. Номера строк не писать руками.
   Проверить, что n-е вхождение — нужная строка (объявление vs определение vs friend).

## Выходы

- `audit/source-audit.md` — карта доменов, точки входа, порядок кадра, ответы на вопросы, новые находки.
- `audit/reference-delta.md` — таблица сверки.
- Записи реестра (`python -I -B docs/AIAtlas/tools/references.py` → 0 failures).
- `audit/progress.md` — снимок, решения, следующий шаг.

## Критерии готовности

- Каждый ответ на контрольный вопрос имеет статус и якорь.
- Нет утверждений «вызывается из …» без найденной строки вызова.
- Все `INFERRED` содержат основание; все `NOT_VERIFIED` объясняют, чего не хватает.
- Реестр резолвится без ошибок; неоднозначные якоря проверены печатью строки.
