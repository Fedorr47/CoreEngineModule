# CoreEngine: QA атласа

Проверки разных уровней не подменяют друг друга: успешная сборка HTML не доказывает корректность AI, наличие
теста не означает его запуск, автоматическая проверка имени не доказывает смысл стрелки.

## Порядок

1. **Дрейф.** `python -I -B docs/AIAtlas/tools/check_drift.py`. При дрейфе перечитать затронутые якоря и главы
   (список ID → главы через поиск `[[ID]]`), обновить реестр и текст; только потом собирать.
2. **Сборка и структура.** `python -I -B docs/AIAtlas/tools/build_site.py` — strict MkDocs, резолв реестра,
   численные проверки (`verify_examples.py`), `validate_site.py` (ссылки/якоря/ресурсы, CDN, обязательные разделы
   глав, символы в схемах, PROPOSED только в главе 20).
3. **Браузер.** `node docs/AIAtlas/tools/qa_browser.js --pages <список> --widths 390,1280,1920,3440 --zoom 1,1.25,2`
   — ошибки JS/консоли, сетевые запросы (заблокированы), overflow страницы, viewer (zoom/fit/reset/expand/Esc/фокус),
   поиск (русский и C++), раскрытие `<details>`, тема, фильтры, демо. Скриншоты — `audit/screenshots/`.
4. **Визуальный обзор.** Открыть и посмотреть скриншоты плотных схем и таблиц: наложения подписей, обрезанный
   текст, нечитаемый масштаб, пропавшие столбцы. Автоматика этого не ловит.
5. **Смысловой обзор схем.** Для каждой новой/изменённой схемы сверить порядок вызовов и направление стрелок с
   выдержками кода; отметить в `audit/coverage.md`.
6. **Движок (по возможности).** Сборка тестов и запуск релевантных GoogleTest (см. `CLAUDE.md`); результат
   фиксировать с датой, ревизией, командой и окружением как `EVIDENCE_VERIFIED`. Не создавать и не менять
   engine-тесты ради документации.

## Отчётность

- `docs/AIAtlas/audit/validation.md`: таблица «команда/действие → PASS/FAIL/NOT_RUN → что проверено →
  ограничения». Не сворачивать в общий PASS. Причину `NOT_RUN` указывать явно.
- `docs/AIAtlas/audit/coverage.md`: по главам раздельно — текст написан, источники проверены, теория,
  схема, ссылки прошли, visual QA.
- `git diff --check` и `git status` — подтверждение, что изменены только документация, её инструменты и skills.

Pressure cases для самопроверки skill-набора: [references/pressure-cases.md](references/pressure-cases.md).
